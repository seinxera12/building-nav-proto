### 6. Build `QRScanner` Component

- [ ] Create `frontend/src/components/QRScanner.jsx`.
- [ ] Props:

```js
{
  onScan,   // called with decoded QR string
  onClose,  // called when user closes scanner
  onError   // called with user-facing camera error
}
```

- [ ] Use refs for:
  - `<video>`;
  - hidden `<canvas>`;
  - `requestAnimationFrame` ID;
  - `MediaStream`.

- [ ] Camera setup:
  - call `navigator.mediaDevices.getUserMedia`;
  - request rear camera with `facingMode: { ideal: 'environment' }`;
  - request ideal `1280x720`;
  - assign stream to `video.srcObject`;
  - call `video.play()`;
  - set status to `active`.

- [ ] Scan loop:
  - run with `requestAnimationFrame`;
  - wait for `video.HAVE_ENOUGH_DATA`;
  - draw current video frame to canvas;
  - read image data with `willReadFrequently: true`;
  - call `jsQR(imageData.data, imageData.width, imageData.height, { inversionAttempts: 'dontInvert' })`;
  - on decoded `code.data`, stop camera, call `onScan(code.data)`, and return.

- [ ] Cleanup:
  - cancel RAF on unmount;
  - stop all media tracks on unmount;
  - stop camera on successful scan;
  - stop camera when scanner closes by unmounting.

- [ ] UI:
  - full-screen black overlay;
  - `<video playsInline muted>`;
  - hidden canvas;
  - centered square viewfinder;
  - visible status text for requesting, active, and error states;
  - close button;
  - camera-denied fallback message with a button that calls `onClose`.

**Acceptance criteria**

- [ ] Scanner opens without forcing iOS fullscreen video.
- [ ] Scanner detects screen-displayed generated QR PNGs.
- [ ] Camera indicator turns off after scan or close.
- [ ] Camera permission denial shows a controlled message.

### 7. Add Navigation State Machine to Store

- [ ] Extend `frontend/src/store/useNavStore.js`.
- [ ] Add explicit navigation statuses:

```js
IDLE
LOCATED
NAVIGATING
REROUTING
ARRIVED
```

- [ ] Initial state:
  - `status: 'IDLE'`;
  - `error: null`;
  - keep existing `currentNodeId` fallback for map rendering, but treat the user as unlocated until first QR scan.

- [ ] Add actions:
  - `handleScan(qrCode)`;
  - `setError(messageOrNull)`;
  - `reset()`.

- [ ] Update `selectDestination(nodeId)`:
  - compute route from `currentNodeId`;
  - set `status: 'NAVIGATING'` when route succeeds;
  - keep current search reset behavior.

- [ ] `handleScan(qrCode)` behavior:

| Current state | Scan result | Required behavior |
|---------------|-------------|-------------------|
| `IDLE` | registered QR | set current node, set `LOCATED`, clear error |
| `LOCATED` | registered QR | update current node, remain `LOCATED`, clear error |
| `NAVIGATING` | destination QR | set `ARRIVED`, progress `100`, update current node |
| `NAVIGATING` | expected checkpoint | update current node, advance step, update progress |
| `NAVIGATING` | on route but not checkpoint | update current node and progress |
| `NAVIGATING` | off route | set `REROUTING`, compute new route to original destination |
| `REROUTING` | any scan | either ignore with message or process after reroute completes |
| `ARRIVED` | any scan | ignore or treat as new location only after reset |

- [ ] QR scan failures:
  - catch unknown QR errors;
  - set `error: 'QR code not recognised. Try another checkpoint.'`;
  - do not mutate current route/location.

- [ ] Add floor-data guard:
  - if `floor` is not loaded, show a loading error and skip state transition.

- [ ] Add catch-all logging:

```js
console.warn(`Unhandled scan in status: ${status}`, scanResult);
```

**Acceptance criteria**

- [ ] First QR scan anchors the current-location dot.
- [ ] Route creation moves state to `NAVIGATING`.
- [ ] Checkpoint scan advances instruction panel.
- [ ] Destination scan shows arrival state.
- [ ] Off-route scan reroutes from scanned node to original destination.

## Public Interface Summary

### Backend

| Endpoint | Method | Purpose |
|----------|--------|---------|
| `/scan` | `POST` | Resolve QR code string to node/location |
| `/map/floor/{floor_id}` | `GET` | Return floor data plus `qrCodes` |
| `/event` | `POST` | Optional non-blocking analytics/demo event logging |

### Frontend Store

| Store field/action | Purpose |
|--------------------|---------|
| `status` | Current navigation state |
| `error` | User-facing scan/navigation error |
| `handleScan(qrCode)` | Central QR state machine |
| `setError(messageOrNull)` | Dismiss or set UI error |
| `reset()` | Clear route and return to clean state |

### Frontend Components

| Component | Purpose |
|-----------|---------|
| `QRScanner.jsx` | Camera scanner and QR decode loop |
| `ArrivedScreen.jsx` | Completion/reset overlay |
| `FloorMap.jsx` updates | Demo-mode tappable QR markers |
| `App.jsx` updates | Scanner overlay, scan button, errors, rerouting, arrival |
